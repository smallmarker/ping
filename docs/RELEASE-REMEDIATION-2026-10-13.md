### 2026-10-14 免费体验版适配

用户随后明确要求“适配下”，授权在不更改套餐与 3 秒限制的前提下调整两个函数。

- sendReminder：每次最多发送一条；主路径数据库往返由多次全局维护 + 领取/发送阶段两次条件更新，缩减为一次读取、一次原子领取和一次结果回写。新领取直接标记 dispatching，进程硬中断时按未知结果恢复，不将“可能已发”自动重发。确定未发的旧 claimed 租约仍可恢复，但留给下一轮发送。
- 优先发送，空闲轮次才维护一条旧锁/过期状态。软工作预算 2.2 秒，扣除首次模块加载耗时；剩余时间不足时不领取或释放明确未发送的领取。微信请求超过剩余软预算则记 unknown，留回写余量；Promise 超时不取消实际请求。数据库请求/平台冷启动仍可能超过硬限制，必须观察真实日志，不能声称绝对不会超时。
- privacyMaintenance：取消 40 秒循环和逐条删除，单次最多 10 条，使用一次查询 + 一次带 ID 白名单及到期条件的批量删除；查询耗时过长则延后。已上传每日触发器不改，不删除缺少 expiresAt 的历史反馈。
- 隔离回归：36 个顶层测试全部通过，新增 8 项验证批次上限、读写次数、慢读取/慢领取延后、并发调度防重复、领取前删除不发送、永不返回的微信调用、批量到期清理及并发修改到期条件。模拟微信无响应约 1.8 秒结束并记录 unknown，后续不重发。不是实际云端耗时证明。
- 试用容量边界：最多约一条/分钟；同时到点记录会排队，超过五分钟有效窗口可能错过。每天反馈清理超过十条会积压。若流量增长，需要调整调度/批量策略并同步核验保留期，不要求当前试水阶段购买套餐。
- 本节追加验证结果不撤销原发布门槛；依赖风险、后台隐私安全与新用户真机验证仍未全部完成。
- 两个适配函数已通过 IDE CLI 更新成功，未开通套餐、未改超时、未改触发器文件、未创建真实测试提醒或批量清理历史数据。部署前云代码备份为 `.release-backups/cloud-before-free-tier-20261014.tgz`。下一步以用户新建的单条未来提醒和平台日志验证冷启动耗时、授权到送达链路；本地模拟通过不等于 3 秒云端绝不超时。

## 已落实

- 隐私政策独立页面及「我的」菜单跳转；运营者为用户确认的个人张龙，公开联系微信 smallmarker。说明规则解析、必要数据、通知边界及权利渠道；未增加虚构用户协议。
- 首页剪贴板改为主动点击后读取，本地预览与云端解析分离；关闭 `traceUser`，移除不实的“发送给 AI”文案。
- 创建采用用户归属与请求 ID 的确定性文档 ID，处理并发幂等和响应丢失重试；同请求内容变化返回冲突，已删除请求不能重新创建。
- 修改、完成、删除采用当前状态及版本条件更新，防止旧请求恢复删除记录；本次明确拒绝通知不会被历史授权覆盖。
- 删除清除标题、地点、备注、原始句子和正文相关错误/指纹，只保留必要标记；仅在用户后续主动删除时执行，不追溯批量清理历史记录。
- 列表增加时间及文档 ID 双字段稳定游标，前端完整分页成功后替换缓存；详情按 ID 独立查询，不依赖列表读取成功。统计使用云端计数，不以第一页长度作为全量数据。
- 编辑页校验实际通知时间，时间/提前量变化时重新校验，保存前再次校验，过期时不请求订阅授权。
- 发送租约区分 claimed/dispatching，确定未发送的超时领取可恢复；发送结果不明确或发送成功后数据库回写失败，不盲目重发。详情展示通知状态与恢复说明，业务完成状态保持独立。
- 新反馈设置 180 天后的 `expiresAt`；新增 `privacyMaintenance` 仅清理带该字段的到期反馈，拒绝非微信定时器调用。不触碰没有该字段的历史反馈和任何提醒。每日定时器是否已上传仍待核验。
- 所有云函数固定 `wx-server-sdk` 4.0.2，并生成依赖锁文件。锁版本不等于依赖没有安全问题，见下节。

## 新发现：仍需整改/核验

1. **运行配置**：sendReminder 和 privacyMaintenance 建议超时 60 秒（代码主动停止领取工作预算为 40 秒），改为平台支持且仍维护的 Node.js 运行时并回归。不要把配置调整与付费套餐升级混为一谈。其他 CRUD 函数也需核验实际超时。
2. **反馈清理触发器**：在 IDE 的 `cloudfunctions/privacyMaintenance/config.json` 上传 `pingFeedbackRetentionDaily`，每天 03:00。函数代码已部署不代表触发器已上传；仍须以微信来源运行日志证明任务工作。无需为了验证清理而创建已过期真实反馈或删除旧数据。
3. **依赖风险**：本次 `npm audit --omit=dev` 对新锁文件报 5 个 high、1 个 moderate（包含传递依赖影响，非六个独立可利用入口）。wx-server-sdk 最新 4.0.2 固定 @cloudbase/node-sdk 3.17.2；查询到 node-sdk 新版 3.18.3 仍依赖 axios 0.27.2，lodash.set 最新 4.3.2 亦在报告内。自动建议是降级 SDK 到 2.5.3，不采用未经兼容测试的强制降级。需要评估受影响调用路径或经 SDK/通知/数据库集成测试的依赖修复方案。
   - 本项目仅使用固定集合、字段、查询和经校验的值，没有公开任意 URL/SDK 调用或实时 watch 接口；这可限制部分路径，不能据此声明所有依赖风险已消除。
   - 安全依据：[Axios 官方安全公告](https://github.com/axios/axios/security/advisories/GHSA-pf86-5x62-jrwf)、[原型污染读取链公告](https://github.com/axios/axios/security/advisories/GHSA-898c-q2cr-xwhg)。最终应按实际可达路径和修复版本复核。
4. **后台安全与隐私**：确认两个集合客户端直接读写被禁止（前端使用云函数），函数按用户隔离、查询索引、告警、备份保留、环境有效期与预算；公众平台隐私指引与实际功能一致。当前未改权限，也未把待核验项当成不存在。
5. **发布与真机**：备案、类目/名称/图标、隐私声明流程；新用户 iOS/Android 体验版分别测试保存接受/拒绝、到点通知、点击通知详情、编辑/删除返回刷新、剪贴板拒绝和数据归属。完成后重新评估，再由用户确认提审与发布。
