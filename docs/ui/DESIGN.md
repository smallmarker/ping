# Ping UI Design Source

> **视觉实现强制规范**：开发任何用户可见页面或组件前，必须先阅读并遵守 [VISUAL-DESIGN-SPEC.md](./VISUAL-DESIGN-SPEC.md)。本文件定义产品结构与页面设计源；视觉 token、中文排版、组件外观和验收以该规范为准。

本文件是 Ping 小程序的产品结构与页面设计源；视觉实现遵循 `VISUAL-DESIGN-SPEC.md`。后续改动应先更新相应设计文档，再修改 `miniprogram/` 中的页面与组件。

## 产品认知

- **阶段**：V1 开发中
- **主要用户**：需要记住生活琐事、但不想维护复杂 Todo 的用户
- **核心对象**：一句自然语言、一个提醒、一个到点通知
- **核心路径**：输入或粘贴一句话 → Ping 解析 → 快速确认 → 保存 → 微信提醒
- **首要任务**：用最少操作把“怕忘”变成“已设好”
- **产品气质**：温柔、轻盈、可靠、克制；像替用户认真写下的一张小记页
- **不要出现**：项目管理、任务看板、复杂筛选、AI 聊天、数据仪表盘、过多设置

## UI 基础

- 设计基准：375px 宽的微信小程序页面
- 页面左右内边距：20px
- 卡片间距：16px
- 标题到内容间距：12px

## Ping Note 小记页

提醒的核心视觉容器是 **Ping Note**：像用户在漂亮、克制的小记页上记下一件事，而非系统表单。

- 暖白纸张卡片，16–20px 圆角
- 可使用 4%–6% 透明度的细点阵或横线纹理
- 一角仅保留一处轻装饰：日期印记、图钉或点状波纹
- 不使用真实手写字体、贴纸堆叠、复古泛黄纸张或性别刻板装饰
- 标题优先，时间为轻量元信息；地点仅在有值时出现
- 已提醒小记页添加低饱和绿色只读“已提醒”印记；旧版手动完成记录保留“历史已完成”，不改写为通知成功

## 品牌标志

- 图标：圆角小记页、右上珊瑚色提醒圆点和两道短脉冲，表达“记下，再 Ping”。
- 主色：暖白 `#FFF9F5`、珊瑚 `#F28C82`、深墨 `#322E2D`、淡紫 `#F4F0FA`。
- 位图应用图标：`miniprogram/assets/ping-logo-v1.png`；用于小程序内头像等位图场景。
- 横版字标：`miniprogram/assets/ping-wordmark.svg`；用于网页、宣传图和可缩放场景。
- 微信公众平台 App 图标需在后台单独上传，不由项目代码发布。
- 「我的」页使用圆形品牌徽章而非伪用户头像；首页仅保留一次 `Ping` 字标，不重复堆放图标。

## 页面规范

### 首页

首页只回答一个问题：**“你想记住什么？”**

1. 品牌区：小字 `Ping`、主问题 `你想记住什么？`、说明 `写一句话，Ping 会在合适的时候提醒你。`
2. 主输入卡：卡片左缘以三枚低对比半圆装订环、左侧记事线和四条等距低对比书写基线构成小记页。首尾环心分别锚定首末基线，中间环落在第 2、3 条基线中点；示例直接作为输入提示，多行内容按需增高。右下角固定使用无文字的「Ping 一下」品牌图标：浅色圆形底、珊瑚色 P 与三道传播线；不使用宽大的提交按钮或重复的动作标签
3. 剪贴板：仅在用户点击 `使用剪贴板` 后读取，返回首页不自动读取。先展示本地预览，确认使用后填入输入区，点击 Ping 才发送内容解析。
4. 提醒列表：最新创建的提醒在前，同日期组内按创建时间倒序，日期组按组内最新创建记录排序。过去日期保留真实日期并标注 `已过期`，不得归入今天；当天标题为 `今天`；未来日期直接使用 `9月12日 · 周五` 这类日期标题，跨年时显示年份。每个日期分组内使用紧凑 Ping Note 卡片，时间最突出；没有事项的日期不展示空分组
5. 提醒记录入口：与待提醒日期分组分离，弱化展示但必须可点击，进入独立的提醒记录页；包含通知成功和旧版手动完成记录

首页最多预览最新创建的 3 条尚未成功提醒的记录，保留日期分组和分组实际数量；超过 3 条时放置弱操作 `查看更多`。点击进入第一条未展示提醒的详情页，随后可在统一提醒册翻阅全部未删除事项。仅 `notifyStatus=sent` 自动进入提醒记录列表，不以时间已到或授权成功代替发送结果；未授权、失败、错过和结果不确定仍留在首页供用户修正。首页返回及下拉时核对云端状态。

输入区和横线统一使用卡片内 `32rpx` 起点及 `48rpx` 行高，关闭原生 textarea 的 iOS 默认内边距，文字与 placeholder 同字号、同行高；不按开发/体验版本分别设置样式。以文字底部距横线约 `6–8rpx` 为真机验收目标，单行、多行都需核对。保存经云端确认成功后，在下一次返回首页时清空与已提交原句相同的输入、解析提示及剪贴板预览；取消或失败不清空，也不误删用户后来输入的其他草稿。

解析 loading 只影响输入卡与按钮，不淡化整页。网络异常保留输入和已加载内容，使用输入卡附近的轻量重试提示。

### 确认提醒

默认不展示完整表单。

1. 显示完整 Ping Note 摘要：标题、日期时间、已识别地点
2. 主按钮：`确认提醒`
3. 唯一次操作：页面标题右侧的 `修改提醒`，作用于整条提醒，不放在事项描述一行旁边
4. 用户点击次操作后，才展开标题、日期、时间、地点、备注与提前提醒
5. 时间缺失时只进入“补充时间”步骤，提供建议时间和“选择其他时间”
6. 通知授权不阻断保存：明确提示“提醒会保存，但可能无法收到通知”
7. 解析推断必须可见：沿用摘要卡下方温和提示区展示 `parseWarnings`；缺失时间显示实际补全原因。保存前校验实际通知时间（事项时间减提前量），已过期则禁用提交并引导唯一的 `修改提醒` 入口。用户编辑并保存后清除旧解析提示。

编辑页同样在日期、时间及提前量变更后校验实际通知时间，点击保存时再次校验；校验通过才请求通知授权，避免时间已过仍消耗授权操作。通知链接打开详情应先按记录 ID 查询，不依赖提醒册分页成功；提醒册不可用时仍可查看该条记录并重试加载。

### 提醒详情

- 详情只有一本提醒册，包含全部未删除事项，不再按已提醒/待提醒分册。按创建时间正序排列，最新创建的事项在最后一页；左滑查看更新页，右滑查看更早页。从首页、历史列表或通知进入均按 ID 直接定位。状态变化不会令书页从册中消失，不改变首页和历史列表各自的筛选及倒序展示。
- 创建时间相同以记录 ID 固定排序；缺失/无效创建时间的旧记录排在前面，不使用会随编辑变化的提醒时间作为排序依据。
- 以完整 Ping Note 展示提醒内容
- 显示可折叠原始内容与通知状态
- 不再提供手动完成、恢复完成操作；用户保存后不必回来确认办完
- 纸页右下为只读状态文字，不使用圆形按钮、勾选热区；待提醒、发送中、已提醒、未开启、失败、错过、结果未确认分别如实展示
- 已提醒表示微信接受通知，并非用户已阅读或事情已完成；保留通知时间和卡片下说明
- 保留唯一纸页右上 `编辑` 入口及编辑页删除确认；失败或过期通过编辑重新设定时间
- 历史 `status=completed` 保留原数据和完成时间，用“历史已完成”区分，不能据此统计已提醒

### 我的与共创

V1 仅包括：品牌徽章、创建数、已提醒数、`一起把 Ping 变得更好`、隐私政策、关于 Ping、版本号。已提醒数只统计未删除的真实发送成功记录，不包含仅手动完成的历史记录。独立用户协议为可选项；当前移除未实现的空入口，隐私政策与后台隐私保护指引仍需完整可访问。

隐私政策使用暖白可滚动正文，不增加卡片墙或强制同意按钮。运营者为个人张龙，联系微信 smallmarker；明确 OpenID、提醒信息及反馈的用途，说明规则解析并非第三方 AI。新版本删除提醒清除正文，仅保留必要的防重放删除标记；反馈入口自 2026-10-16 起使用微信原生反馈，由微信接收，运营者在公众平台查看。旧自建反馈已有的 180 天到期规则继续执行，缺少到期时间的历史数据不自动批量清理，用户可通过联系渠道提出删除申请。后台隐私指引需要在提审前同步核验，不能以页面正文代替平台配置。

`关于 Ping`从「我的」页进入，使用独立页面与胶囊安全区内居中的标题。页面中轴依次展示浅桃色圆形 P 品牌标识、`Ping`、一句话 `把想记住的事，轻轻 Ping 一下。`；下方用两行短说明 `一句话记下想做的事，\n在合适的时候提醒你。`，再展示版本 `版本 V1.0.0`。版权 `© 2026 Ping` 独立贴近底部安全区。除返回外不增加操作、卡片或联系方式；大块暖白留白是版式的一部分。

共创入口保留现有淡紫卡片、标题 `一起把 Ping 变得更好` 和说明 `有一个你希望它记住的新场景吗？`。使用原生 `button open-type="feedback"` 直接打开微信反馈页，不经过自建填写页；按钮需重置原生居中、行高、边距和边框，避免入口视觉变化。提交与取消由微信反馈页处理，不在入口点击或返回后伪造“提交成功”提示。旧表单路由已注销，旧版源码、提交接口及历史数据清理任务暂留用于兼容旧客户端；不得因此再次暴露双重入口。

## 实现与验收规则

- 先复用项目已有组件；新增重复 UI 必须抽为组件
- shadcn 仅作为结构、状态与可访问性参考，不复制默认 Web 视觉
- 主操作必须在移动端首要可达位置
- 每个页面必须有 loading、empty、error、long-text 的表现
- 删除操作需确认；授权拒绝必须给出可继续的路径
- 删除对用户不可恢复：立即清除事项正文，保留不含正文的必要删除标记，防止旧请求使记录重新出现；不批量清理已有历史数据
- 数据统计失败时只能显示明确的失败与重试，不能以 `--` 伪装为正常数据
- 共创反馈直接进入微信原生页；不读取或推断其提交结果，不以本地 Toast 代替真实提交；真机验证入口及返回路径
- 完成一次 UI 改动后，必须在微信开发者工具或等效预览中检查 375px 宽布局
