# Ping 视觉 UI 设计规范

> **适用范围**：Ping 微信小程序 V1 所有用户可见页面与组件。
>
> **优先级**：产品流程与字段以 [PRD](../Ping-V1-PRD.md) 为准；本规范定义视觉表现与交互控件外观。若旧页面样式与本规范冲突，以本规范为准。
>
> **设计基调**：温柔、轻盈、可靠、克制。Ping 是把一句话认真写下并准时提醒的工具，不是 Todo、项目管理工具或数据仪表盘。

---

## 1. 设计原则

1. **像一张被认真使用的小记页，而非系统表单。**
   用暖白纸张、细边界、少量横线和装订环建立记事感；不能堆贴纸、手写字、插画或复古纸张纹理。
2. **先让用户确认，再让用户操作。**
   页面只突出当前最重要的信息与一个主操作；次操作使用文字或弱样式。
3. **女性化来自克制和触感，不来自幼态化。**
   使用低饱和珊瑚色、暖灰文字、柔和留白；禁止纯黑大标题、甜腻粉紫渐变、过度圆润的“可爱风”组件。
4. **少即是快。**
   Ping 的价值是“一句话 → 确认 → 提醒”。不添加任务分类、数据看板、复杂筛选或多层级表单。
5. **状态必须可见且可信。**
   保存、解析、授权、失败、完成、空状态必须有明确样式；不以空白、`--` 或 Toast 替代页面状态。

## 2. 设计基准与布局

### 2.1 画布

| 项目 | 规则 |
| --- | --- |
| 设计基准 | 375px 宽微信小程序，开发统一换算为 rpx |
| 页面背景 | 全页 `#FFF9F5`，不可使用纯白大底 |
| 左右页面边距 | `40rpx`（20px） |
| 常规模块间距 | `48rpx`（24px） |
| 卡片间距 | `32rpx`（16px） |
| 标题与说明间距 | `12rpx` |
| 卡片内边距 | 默认 `32rpx`；摘要卡可用 `40rpx` |
| 底部安全区 | 固定操作栏需包含 `env(safe-area-inset-bottom)`；内容与操作栏至少 `64rpx` |

### 2.2 间距系统

所有间距只能使用 4 的倍数，优先以下 token：

| Token | rpx | 常见用途 |
| --- | ---: | --- |
| `space-1` | 8 | 图标与文字、小元素微调 |
| `space-2` | 16 | 行内内容间距 |
| `space-3` | 24 | 标签与值、紧凑模块 |
| `space-4` | 32 | 卡片内边距、卡片间距 |
| `space-5` | 40 | 标题区内部 |
| `space-6` | 48 | 页面模块间距 |
| `space-8` | 64 | 大区块与底部操作区 |

禁止依赖肉眼随意填 `18rpx`、`34rpx`、`46rpx` 等孤立数值；确有光学校正时需在样式注释中说明。

## 3. 色彩系统

### 3.1 基础色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--ping-bg` | `#FFF9F5` | 页面暖白背景 |
| `--ping-surface` | `#FFFFFF` | 卡片、弹层、底部操作栏 |
| `--ping-paper` | `#FFFCFA` | 小记页内层、输入纸张 |
| `--ping-primary` | `#F28C82` | 唯一主操作、品牌强调、激活状态 |
| `--ping-primary-pressed` | `#DE746B` | 主操作按下态 |
| `--ping-primary-soft` | `#FFF0EB` | 轻提示、选中背景 |
| `--ping-lavender` | `#F4F0FA` | 共创、低优先提示区域 |
| `--ping-success` | `#77AF91` | 完成、通知已开 |
| `--ping-warning` | `#D9A35D` | 待补充、时间风险 |
| `--ping-error` | `#D67D76` | 失败、删除风险 |
| `--ping-border` | `#F1E8E3` | 卡片边界、分割线 |
| `--ping-rule` | `#EEE4DE` | 小记页书写基线 |
| `--ping-margin-line` | `#F7D9D3` | 小记页左侧页边线 |

### 3.2 文本色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--ping-ink` | `#463B39` | 标题、主要内容、图标线条 |
| `--ping-ink-strong` | `#382F2D` | 仅用于时间等关键值，禁止大面积使用 |
| `--ping-text-secondary` | `#8D817C` | 标签、说明、次级内容 |
| `--ping-text-tertiary` | `#ADA19B` | placeholder、禁用、极弱辅助 |
| `--ping-on-primary` | `#FFFFFF` | 珊瑚主按钮上的文字 |

### 3.3 色彩使用规则

- **禁止纯黑** `#000000` 作为任何正文、标题或图标颜色。
- 珊瑚色只服务于：主操作、选中状态、品牌动作、少量关键提示；同一屏通常不超过 2 处高饱和珊瑚区域。
- 正文不可使用珊瑚色；错误信息使用 `--ping-error`，成功信息使用 `--ping-success`。
- 卡片只使用白色与细边界。除小记页和浮层外，不使用明显投影制造层级。

## 4. 中文排版规范

### 4.1 字体家族

使用微信系统中文字体栈，不下载、不依赖手写字体：

```css
font-family: -apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB",
  "Microsoft YaHei", sans-serif;
```

**设计判断**：Ping 的“笔记感”由纸张、基线与装订结构表达，不由难以读取或跨端不稳定的手写字体表达。

### 4.2 字体层级

| 样式 | 字号/行高 | 字重 | 颜色 | 使用位置 |
| --- | --- | ---: | --- | --- |
| `display` | `40rpx / 56rpx` | 600 | `--ping-ink` | 页面主标题，如“确认提醒” |
| `page-title` | `36rpx / 52rpx` | 600 | `--ping-ink` | 普通页面标题 |
| `section-title` | `32rpx / 48rpx` | 600 | `--ping-ink` | 首页问题、分组标题 |
| `card-value-strong` | `34rpx / 48rpx` | 600 | `--ping-ink-strong` | **每卡最多一项**关键时间/状态 |
| `card-value` | `32rpx / 48rpx` | 600 | `--ping-ink` | 事项标题、主要值 |
| `body` | `30rpx / 44rpx` | 400 | `--ping-ink` | 正文、输入内容 |
| `label` | `25rpx / 36rpx` | 500 | `--ping-text-secondary` | 字段标签、次级标题 |
| `supporting` | `26rpx / 40rpx` | 400 | `--ping-text-secondary` | 页面说明、日期、帮助文本 |
| `caption` | `24rpx / 36rpx` | 400 | `--ping-text-tertiary` | placeholder、极弱说明 |
| `action-text` | `26rpx / 40rpx` | 500 | `--ping-primary` | 修改、文字操作 |
| `button` | `32rpx / 48rpx` | 600 | `--ping-on-primary` | 主按钮 |

### 4.3 排版硬规则

- 标题只使用 600；**禁止** 700、800、900 的黑体大字。
- 一个信息卡内只允许一个 `card-value-strong`；不要把事项、时间、提前提醒都做成同样粗黑大字。
- 结构标签必须比其对应数值更小、更浅。
- 关键时间优先使用自然语言：`明天 03:00`、`今天 18:57`；日期作为次级行，如 `9月9日 · 周三`。跨年或需要消除歧义时才显示年份。
- 提前提醒用自然语言展示：`不提前`、`提前 5 分钟`、`提前 2 小时`；避免 `提前 120 分钟`。
- 单行中文溢出使用省略号；标题最长两行。不得通过缩小字号使长文塞进一行。
- 所有文本必须保持可读对比度；`caption` 不承载关键决策或错误信息。

## 5. 形状、边界与阴影

| 元素 | 圆角 | 边界/阴影 |
| --- | --- | --- |
| 普通卡片 | `32rpx`（16px） | `2rpx solid --ping-border`，无阴影 |
| 小记页输入卡 | `32rpx` | `2rpx solid --ping-border`，可用极弱投影 |
| 底部抽屉 | 顶部 `40rpx` | 白底，顶部弱阴影 |
| 主按钮 | `24rpx`（12px） | 无描边；高度 `96rpx` |
| 次按钮 | `24rpx` | `2rpx solid --ping-border` 或透明文字按钮 |
| 品牌 Ping 图标按钮 | 圆形 `88rpx` 点击区 | 使用既有 P + 三道传播线标志；不得替换为通用铃铛、加号或文字胶囊按钮 |

允许的唯一明显阴影：

```css
box-shadow: 0 12rpx 40rpx rgba(91, 61, 47, 0.08);
```

不可在每一张卡片上都加阴影；这会让小程序变得厚重且廉价。

## 6. 核心组件规范

### 6.1 页面顶部

- 使用微信小程序原生导航承载返回与胶囊按钮区域；自定义内容从安全区后开始。
- 中间品牌名 `Ping` 为常规字重 `28rpx / 400`，不用作大标题。
- 页面主标题与顶部导航至少间隔 `80rpx`。
- 页面标题下可有一行简短说明；说明只解释当前要确认/补全的事，不写产品口号。

### 6.2 主按钮与次操作

| 类型 | 规范 |
| --- | --- |
| 主按钮 | 96rpx 高、珊瑚底、白字；每屏最多 1 个。文案是当前动作，如“确认提醒”“保存修改”。 |
| 按下态 | 使用 `--ping-primary-pressed`，不改变尺寸与圆角。 |
| 禁用态 | 背景 `#F7E6E1`，文字 `#C8BDB8`；不可伪装为可点击。 |
| loading | 保持按钮宽高与文案区域，不造成跳动；显示加载指示与“正在保存”。 |
| 文字次操作 | `action-text`，不用和主按钮相同尺寸的描边按钮；例如“修改”。 |
| 风险操作 | 删除必须使用弱文字入口，二次确认弹层内才可使用错误色主按钮。 |

### 6.3 Ping Note（小记页）

小记页是 Ping 的品牌容器，不是每个页面都必须使用的背景。

- 纸面：`--ping-paper` 或白色；边界 `--ping-border`；最大圆角 `32rpx`。
- 首页输入卡：左侧 `80rpx` 处绘制细页边线；使用 **4 条独立、等距**书写基线，统一 `--ping-rule`。
- 左缘装订环使用 **3 枚低对比半圆环**：首、末环对齐首末基线，中环居中于中部留白；不能与四条基线逐条对应，避免“梳齿感”。
- 输入光标、placeholder 和首条基线必须保持同一书写行；文字底部与横线保留约 `6–8rpx` 间距，横线不得穿过文字。字符计数固定贴近卡片底部左侧，不得悬在书写区中间。
- 首页输入区与横线统一 `32rpx` 起点，关闭 textarea 的 iOS 默认内边距；保持输入/placeholder 同字号、同 `48rpx` 行高，避免只在模拟器看起来分离。保存成功才清空相应草稿，取消/失败保持原句。
- 右下角固定使用用户确认的 **Ping P + 传播线图标**，点击热区不小于 `88rpx × 88rpx`；无文字、无圆角胶囊背景。
- 详情/确认摘要卡只借用“纸张”语义；不强制加横线与装订环，避免视觉噪声。

### 6.4 确认提醒摘要卡

确认页目标是“确认解析结果”，不是编辑表单。

1. 卡片内顺序：`提醒事项` → `提醒时间` → `提前提醒`。
2. 事项与时间由解析结果直接显示；用户输入“明天 3:00”时，默认提醒即为 **明天 3:00**。
3. `提前提醒` 默认值必须是 **不提前**；用户在原句明确写出“提前十分钟”等也属于主动选择，解析后显示相应提前量，不擅自添加。
4. `提醒时间` 是卡片内唯一允许使用 `card-value-strong` 的字段；事项使用 `card-value`，提前提醒使用普通 `card-value` 或 `body`。
5. 只保留一个编辑入口：页面标题区右侧 `修改提醒`，与标题垂直居中，点击热区至少 `88rpx` 高。入口不归属于事项描述行，以明确它作用于整条提醒；事项、提醒时间与提前提醒三行均为只读展示，**不添加箭头、点击态或其他入口**。
6. `修改提醒` 后进入独立编辑页/展开页；日期、时间、事项、地点、备注、提前提醒均可编辑。
7. `自定义提前时间`使用底部抽屉：顶部仅展示静态的原始提醒时间；滚轮下方只出现一条动态结果，如“将在明天 01:00 提醒你”。禁止重复表达同一时间结果。
8. 摘要卡下方使用既有温和提示区显示时间推断和补全原因：浅桃背景、`supporting` 文字与行高、正常换行。提示不增加操作按钮，仍由唯一的 `修改提醒` 入口修正；未解决的过期通知时间禁用确认。用户手动保存修改后清除已解决的解析提示。

### 6.5 提醒详情（提醒册）

提醒详情不是设置摘要页，而是一册可浏览的个人提醒记录。

1. 每一条提醒对应一张完整的 **Ping Note 页面**；一本书包含全部未删除的待提醒、已提醒及异常记录。从首页、提醒记录或通知进入均定位该条所在页，不再按状态分册，也不让发送后的书页消失。
2. 页面主体优先展示用户的原始记录句；使用系统中文字体与书写基线，不使用手写字体。原句最长两行，超出部分按正常段落换行，不缩字硬塞。
3. 页面使用四条等距书写基线、左侧页边线与三枚低对比半圆装订环；原始提醒原句写在第一条书写线上，文字底部与横线保留约 `6–8rpx` 间距，不让横线穿过文字；余下三条作为留白书写线。三枚环分别锚定首、末基线与中部留白，不得逐条对应四根基线。
4. 提醒册统一按创建时间正序排列，最新创建的记录在最后一页；左滑向更新页、右滑向更早页，不循环越界。首页和历史列表仍倒序展示，点击事项按 ID 定位到书中对应页，修改提醒时间不改变页序。创建时间相同按 ID 固定排序，缺失或无效创建时间的旧记录放在前面。仅在数量大于 1 时显示弱页码（如 `3 / 12`）与左右页缘提示。
5. 原句中的相对时间会过期，因此纸张下方必须以弱结构信息保留准确值：`提醒时间 2026年9月11日 · 15:00`、`提前提醒`、`地点`。不得另起设置卡片重复这些字段。
6. 不再提供手动完成操作。纸页右下角用只读状态文字表达 `待提醒`、`正在发送`、`已提醒` 或通知异常；不使用圆形按钮、勾选图标或按钮点击态。成功状态使用鼠尾草绿，异常使用低饱和风险色，其余使用暖灰。
7. 小程序右上角由原生胶囊按钮占用，禁止在导航栏自建 `编辑`、三点菜单或任何操作。导航栏只放返回与居中 `Ping`；唯一的 `编辑` 入口放在纸页右上角，使用弱色铅笔图标加 `编辑` 文案，并且是整页记录唯一的编辑入口。删除放入独立编辑页的保存区下方，使用带垃圾桶图标的低饱和珊瑚红文字 `删除这条提醒`，不做醒目的红色实心按钮；点击后以底部确认抽屉二次确认：`删除这条提醒？` / `删除后将无法恢复` / 实心 `删除` / 文字 `取消`。
8. 通知状态为 `sent` 后自动进入 `提醒记录`，纸页显示只读 `已提醒` 及发送时间，卡片下说明“微信已接受通知”，不暗示已阅读或事情已完成。旧手动完成数据保留“历史已完成”及原完成时间；不得自动迁移为已提醒。纸面不整体降低透明度，以保留文字对比度。

### 6.6 表单、Picker 与输入

- 文字输入以清晰的标签、已填值和错误信息组成；不使用浮动标签遮挡输入内容。
- 日期与时间为可点击字段，使用系统 picker；已填值用 `card-value`，未填值使用 `--ping-text-tertiary`。
- 提前提醒快捷项为单选 Chip：`不提前 / 提前 5 分钟 / 提前 15 分钟 / 提前 30 分钟 / 提前 1 小时 / 自定义`。
- Chip 高度 `64rpx`，内边距左右 `24rpx`；选中态珊瑚浅底 + 珊瑚文字，不选中态白底 + 边界。
- 校验错误紧贴字段下方，使用 `24rpx`、`--ping-error`；不只靠 Toast。

### 6.7 反馈入口（2026-10-16 调整）

- 从“我的”现有淡紫卡片直接打开微信原生意见反馈页，使用 `button open-type="feedback"`，不再进入自建填写页。
- 保留当前入口文案与卡片排版；重置原生按钮默认居中、行高、左右边距及边框，沿用字体，并提供轻微按压反馈。
- 原生反馈填写页使用微信样式，不仿制或覆盖；入口与返回不得显示未经确认的提交成功提示。
- 新入口不写自建反馈集合；原有反馈数据及清理规则不变。旧表单路由注销，旧接口暂留兼容已上传客户端。
- 开发者工具验证入口布局；原生页打开、取消及提交后后台可见需真机核验，不以模拟器点击成功替代。

### 6.8 我的页

- 统计为次级信息，不可作为顶部主视觉或数据仪表盘。
- 若统计仅有“累计创建 / 已完成”且没有对应数字、解释或可点击价值，则宁可移除，不做空壳双栏卡片。
- 共创入口使用淡紫弱卡片，突出文案“你希望 Ping 还能帮你记住什么？”，而不是官方腔“意见反馈”。
- 品牌徽章是圆形品牌标识，不伪装成用户头像。

### 6.8.1 协议与关于页

- `隐私政策`、`关于 Ping`均为从“我的”进入的独立二级页；若后续增加可选的`用户协议`，也遵守同一布局。二级页均遵守小程序原生胶囊安全区：导航栏仅放返回与居中页标题，禁止自建右上操作。
- `隐私政策`为合规必备页，使用可阅读、可滚动的文档层级而非卡片仪表盘。首屏可用“你的信息，只为帮你记住”说明最小化处理原则，必须覆盖实际处理的信息类别、目的、方式、保存期限、主体名称与联系渠道、用户查阅/更正/删除等权利；文本必须在发布前按真实数据流、后端与主体信息由负责人审核填充，禁止使用虚构主体或联系方式。
- `用户协议`为可选页，不作为本项目统一的发布硬门槛；当前按用户要求移除没有内容的空入口。提醒服务、通知送达与责任边界仍需在使用说明中如实说明，不能宣传保证送达；若未来提供协议，使用温和文档版式，完整内容以发布版本为准。
- `关于 Ping`为最小产品信息页：品牌标识、产品一句话、短说明、版本号、版权即可。不得重复“意见反馈”入口，不得默认展示不存在的开源许可、公司地址或联系方式。

### 6.9 首页提醒列表

- 首页最多展示最新创建的 3 条尚未成功提醒的记录（排除已删除、旧手动完成及 `notifyStatus=sent`）；超过时保留居中 `查看更多`。分组数量仍基于待提醒范围；进入详情则翻阅全部未删除事项。未授权、失败、错过和结果未确认不得因时间已到而移入已提醒记录。

- 首页待提醒事项保留**具体提醒日期**分组，最新创建的提醒在前：组内按 `createdAt` 倒序，日期组按组内最新创建记录排序，不固定把过去日期放在顶部。过去日期使用真实日期标题并标注 `已过期`，不得混入 `今天`；当天标题为 `今天`；之后的日期标题为 `9月12日 · 周五`，跨年时为 `2027年1月3日 · 周日`。过期不等于完成，不能自动改变完成状态。分组标题已表达日期范围，卡片或行内不得重复显示日期或“今天”。
- 每个日期分组标题右侧只显示弱计数，如 `2 项`；不使用“2 个提醒”这类冗余表述。
- 同一分组内的提醒使用紧凑、独立的白色 Ping Note 卡片；卡片高度约 `248–272rpx`，卡片间距 `32rpx`。不要把提醒贴成表格行，也不要做成过高的卡片墙。
- 提醒卡左侧为固定宽度的珊瑚色时间列；右侧依次为事项标题、地点与提前提醒等次级信息。整卡可点击，但不在行尾添加日期、箭头或多余图标。
- 仅渲染有事项的日期分组；没有未来提醒时不展示空标题、空状态或“接下来”占位。
- `提醒记录`与待提醒卡片之间至少留 `96rpx`，其下为透明、无卡片背景的单行回顾入口：弱记录图标、`N 条记录`与 `查看 ›`。记录页各条分别显示 `已提醒` 或 `历史已完成`，不把两者混为通知成功；首页异常事项在次级信息中显示真实状态。

## 7. 图标规范

- 图标优先使用统一线性风格：`40rpx` 视觉尺寸、`3rpx` 左右线宽、圆角端点、`--ping-ink` 或 `--ping-text-secondary`。
- 同一页面的图标线宽、圆角和颜色必须一致；禁止混用填充图标、黑色 emoji、不同风格 SVG。
- 图标是结构辅助，不应比文本值更黑、更粗或更醒目。
- 品牌 Ping 图标是唯一例外，使用珊瑚色以表达主操作。
- 所有仅图标按钮都必须有明确的无障碍标签与最小 `88rpx` 点击热区。

## 8. 页面状态规范

| 状态 | 视觉规则 |
| --- | --- |
| 解析中 | 仅锁定输入小记页及 Ping 图标；保留用户原句；显示“正在理解…” |
| 保存中 | 固定主按钮尺寸，显示“正在保存”；禁止重复提交 |
| 空状态 | 简短、可行动，如“把一句想记住的话 Ping 一下”；不使用大插画占据首屏 |
| 解析失败 | 保留用户原句，并在输入卡下使用浅桃色提示卡：`这句我还没理解好` / `手动补一下，就能设提醒。`；只提供一个 `手动填写` 入口，不显示“重试”。用户若要重试，可再次点击 Ping 图标。 |
| 缺失时间 | 顶部温和提醒“补全时间后即可设提醒”；相应字段显示“请选择”，主按钮禁用 |
| 授权拒绝 | 仍允许保存；说明“提醒已保存，但可能无法收到通知”，提供后续开启路径 |
| 已完成 | 使用低饱和绿色状态印记，内容整体降权；不可让完成态与待办态同等强调 |

## 9. 禁止项

- 纯黑、超粗、大面积大标题。
- 每一行数据都用大号粗体；尤其禁止确认卡的事项、时间、提前提醒同权。
- 无功能的统计卡、仪表盘、进度环或装饰性数据。
- 宽大的“Ping 一下”文字按钮；首页提交使用既有 Ping 图标按钮。
- 通用铃铛/加号替代品牌 Ping 图标。
- 把说明文字写成产品自我解释，例如“无需留下联系方式，写下你的想法就好了”。
- 手写英文字体、花卉、贴纸、人物插画、性别刻板装饰。
- 无规律的横线、与基线一一对应的装订环、未对齐的输入光标/placeholder。
- 一页多个同级珊瑚色按钮、厚阴影卡片墙、无意义渐变。

## 10. 开发验收清单

开发完成每个页面后，必须在微信开发者工具的 **375px 宽预览** 中逐项检查：

- [ ] 背景、文字、边界均使用本规范 token，未出现纯黑。
- [ ] 页面最多一个珊瑚主按钮，按钮文案与当前动作一致。
- [ ] 标题、标签、主值、辅助文本至少有 3 个清晰层级。
- [ ] 卡片内只有一个最强值；时间优先于提前提醒。
- [ ] 所有左右边缘、图标与文字基线、分割线、卡片内边距对齐。
- [ ] 输入、长文本、空态、加载、失败、禁用、授权拒绝均有对应表现。
- [ ] 小记页的四条基线等距，三枚装订环符合定位规则，计数与主操作贴近底缘。
- [ ] 仅图标按钮具有 `88rpx` 点击热区和无障碍标签。
- [ ] 小程序底部安全区、长机型和系统字体放大后仍可操作。
- [ ] 无本规范第 9 节禁止项。
