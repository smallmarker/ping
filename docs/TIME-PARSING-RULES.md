# 时间解析规则与验收边界

版本：rule-fallback-v3，2026-10-12。此文档描述实际实现，不承诺所有自由文本均可理解。

## 解析流程

归一化全角数字/冒号 → 提取完整时长、钟点、日期片段 → 关联日期与时段 → 检查冲突与否定 → 生成候选 → 校验实际通知时间 → 删除已确认片段并保留事项内容。

解析器纯函数位于 `cloudfunctions/parseReminder/parser.js`，云函数入口负责身份与请求校验。不会请求外部模型、不会保存输入、不会直接创建提醒。

## 已支持

- 数字与中文钟点：17:20、17：20、三点55、三点五十五分、三点五五、十五点二十分；全角数字可用。
- 时段：凌晨、早上、早晨、上午、中午、下午、傍晚、晚上、夜里、今晚、明早、明晚。
- 分钟口语：半、一刻、三刻、差五分四点。
- 没有日期或时段的口语 1–12 点：在今天/明天的上午、下午候选中选最近未来时间。明确日期时只在指定日期内选候选；仍显示时段推断提示。
- 冒号默认为 24 小时制；明确时段优先。上午17:20等矛盾组合要求补全。
- 上午/中午十二点为12:00；凌晨十二点为00:00；晚上十二点/零点为当晚结束后的次日00:00，并提示跨日。晚上三点等矛盾口语要求补全。
- 日期：今天/今日、明天、后天、大后天；2026年10月13日、2026-10-13、2026/10/13、10/13、10月13号、13号、下个月1号。
- 星期：周/星期/礼拜一至日，本周/这周/下周/下下周；周一已过可取下一周并提示，本周已过不能顺延。
- 缺年份的月日过期时取下一年并提示；单独日号过期时取下个月并提示。无效日历日期不能自动溢出到下个月。
- 相对时长：五分钟后、过五分钟、半小时后、一个半小时后、一小时半后、1.5小时后、一小时三十分钟后；天/周可作为相对时长，带钟点时作为日期偏移。
- 提前量：提前十分钟、提前一个半小时、十分钟前提醒等。默认不提前；用户明确写出提前量才提取，支持与编辑页相同的一年范围。
- 简单时间修正：三点不行改成四点、不是三点而是四点；采用最后明确修正的钟点，并提示确认。未重新声明时段时继承前一个钟点的时段。
- 日期词只删除与提醒时间关联的片段；事项中的昨天的账单、今晚的饭菜、每天的销售报表、品牌周五福、数量三点五升需保留。

## 安全兜底

- 模糊时间（过一会儿、三点多、左右）、秒级时间、农历、月底/年后等尚未支持的日期、重复提醒、冲突时段、无效日期要求手动选择。
- 无法确定关联的多个时间、时间范围、相对时长与具体时间并存、多个提前量、否定/取消表达要求补全，不直接取第一个时间。
- 提前通知已过、但事项还未到时，不因提前量而静默顺延事项；要求修改时间或提前量。
- 原句缺少事项时要求补充，不能把纯时间当成事项。
- 手动兜底保留原句，`remindAt=null`，含中文原因；不会偷偷生成今天的时间。

## 前端契约

- 确认页展示 `parseWarnings` 和补全原因；推断提示不阻断有效草稿保存。
- 实际通知时间必须晚于当前时间；点击确认时再次校验，过期不请求授权。
- 保存修改后清空旧解析提示；创建失败重试需保留原幂等键。
- 本轮不改变发送通知、订阅授权、数据库结构和首页列表同步逻辑。

## 验证与后续维护

`tests/reminder-parser.test.js` 包含正常表达、手动兜底、时段歧义、日历边界、秒数取整、提前时间过期等测试，以及跨三个基准日的1,296组时刻/提前量组合。`tests/confirm-parse-warnings.test.js` 验证提示呈现、授权前过期拦截、幂等键和手动修改清理提示。既有云函数、通知、列表同步测试必须持续通过。

新支持的表达需同时加入正例和近似反例，检查事项标题、具体ISO时间、提前量、提示/缺失字段，不只检查“成功”。先验证再部署；无法可靠消歧的情况继续手动补全，不宣称规则穷尽所有语言。
